Abstract

This report presents the design, architecture, and implementation of AI Accountant, an intelligent financial management system developed as a graduation project at Akhbar El-Youm Academy, Faculty of Computer Science, in partial fulfillment of the requirements for the Bachelor of Computer Science degree. The system addresses the financial management challenges commonly encountered by small and medium-sized enterprises (SMEs), where affordable, intelligent accounting tools with real-time analytical capabilities remain scarce.

The proposed system delivers a comprehensive suite of accounting functionalities, including real-time Key Performance Indicator (KPI) dashboards, automated transaction classification, AI-driven spreadsheet generation, natural-language financial querying via a conversational chatbot interface, and a versioned in-browser Excel editor. Two AI providers are leveraged: the Groq inference engine running the LLaMA 3.3-70B model for conversational and generative tasks, and Google Gemini for multi-modal document analysis and automated transaction extraction from uploaded financial files.

The system adopts a client-server architecture comprising a React 19 Single-Page Application (SPA) on the frontend and a Node.js/Express 5 RESTful API server on the backend, with data persisted in a MongoDB database via the Mongoose ODM. A tiered subscription model governs feature access, and a versioned public REST API enables programmatic integration by third-party developers. Security is enforced through stateless JWT authentication, bcrypt-hashed credentials, Helmet HTTP security headers, and scope-based API key authorization, all conforming to OWASP Top Ten security guidelines.

The implemented system demonstrates the technical viability of integrating generative AI within a traditional enterprise accounting workflow, substantially reducing manual data-entry overhead and enhancing financial visibility for business operators.

Keywords: Artificial Intelligence, Financial Management, Large Language Models, RESTful API, Single-Page Application, React, Node.js, MongoDB, Groq, LLaMA, Google Gemini, Generative AI, SME Accounting, Natural Language Processing, JWT Authentication.

1. Project Overview

AI Accountant is a full-stack, intelligent financial management system developed to address the accounting and analytical requirements of small and medium-sized enterprises (SMEs). The system synthesizes conventional bookkeeping methodologies with state-of-the-art artificial intelligence capabilities, encompassing automated transaction classification, AI-driven spreadsheet generation, real-time financial Key Performance Indicator (KPI) dashboards, and a natural-language conversational financial advisory interface powered by large language models (LLMs).

This system was conceived and implemented as a graduation capstone project at Akhbar El-Youm Academy, Faculty of Computer Science, during the academic year 2025/2026. It demonstrates the practical application of modern full-stack web engineering principles, distributed system design patterns, and the integration of generative AI language models within a production-grade software architecture.

1.1 Problem Statement & Research Objectives

Small and medium-sized enterprises frequently encounter significant challenges in managing financial operations efficiently. Traditional accounting software solutions are either prohibitively expensive, require dedicated accounting personnel, or lack the intelligence necessary to deliver actionable business insights in real time. The recent proliferation of large language models (LLMs) and generative AI presents a compelling opportunity to augment conventional accounting tools with natural-language interfaces, automated data extraction, and intelligent financial advisory capabilities.

The following primary objectives guided the design and implementation of this system:

📊 Financial Visibility

Provide business owners with real-time KPI dashboards — revenue, expenses, profit margin, cash flow, burn rate, and tax estimates — with month-over-month trend comparisons.

🤖 AI-Powered Analysis

Integrate Groq (LLaMA 3) and Google Gemini AI to enable natural-language financial queries, automatic transaction categorization, chart generation, and spreadsheet creation.

📁 Smart Data Ingestion

Accept Excel (.xlsx, .xls) and PDF financial files, automatically extract and analyze transaction data using AI, and batch-import thousands of records via a background job queue.

🔌 Developer API

Expose a versioned public REST API (v1) secured by API keys, allowing third-party integrations to read/write transactions and retrieve dashboard KPIs programmatically.

1.3 Background & Related Work

The application of artificial intelligence to financial management software has attracted considerable research and industrial interest in recent years. Established commercial platforms such as QuickBooks Online, Xero, and Wave Accounting offer robust bookkeeping functionality but provide limited AI-driven intelligence beyond rule-based automation heuristics. Academic research has investigated LLM-based document information extraction, natural-language interfaces for structured database querying, and supervised machine-learning models for transaction categorization — capabilities that this project unifies within a single cohesive system.

This project builds upon and synthesizes prior work in four principal areas: (i) RESTful API design adhering to Fielding's representational state transfer (REST) architectural constraints for stateless client-server communication; (ii) LLM integration leveraging the Groq inference API (LLaMA 3.3-70B) for text generation tasks and the Google Gemini API for multi-modal document understanding; (iii) modern Single-Page Application (SPA) architecture employing React 19 with optimistic server-state management via TanStack Query; and (iv) security-first backend design conforming to OWASP Top Ten security guidelines including input validation, rate limiting, and zero-knowledge credential storage.

📖
Distinguishing Contribution Unlike existing SME accounting platforms, this system integrates two complementary AI providers within a unified architecture: Groq's LLaMA 3.3-70B for conversational dialogue and generative spreadsheet creation, and Google Gemini for multi-modal financial document parsing. This combination enables end-to-end AI-assisted accounting workflows spanning document ingestion, automated transaction classification, interactive natural-language querying, and on-demand report generation.

ApiKey Model

Developer API keys follow a zero-knowledge storage pattern:

  • Wire format: ak_<32 random hex bytes> (68 chars total)
  • Only the SHA-256 hash of the key is stored in the database
  • The first 10 characters (keyPrefix) are stored as a safe display hint
  • Scopes control access: transactions:read, transactions:write, dashboard:read, excel:read, excel:write, chatbot:read

3.3 Authentication System

Authentication uses stateless JWT tokens with a 72-hour expiry. The system supports both MongoDB-backed and local file-based user storage.

Registration Flow

  1. Client POSTs name, email, password, businessType
  2. Input validated by express-validator rules
  3. Password hashed with bcrypt (10 salt rounds)
  4. User created in MongoDB or local JSON store (dev fallback)
  5. JWT signed and returned to client

Login Flow

  1. Client POSTs email + password
  2. User fetched from store; bcrypt compare performed
  3. On success: JWT (72h) returned; client stores in memory / localStorage
  4. All subsequent requests attach Authorization: Bearer <token>

Password Reset Flow

  1. User POSTs email to /api/auth/forgot-password
  2. Crypto random token generated; SHA-256 hash stored in DB with 1h expiry
  3. Plain token sent via email link (Nodemailer / Resend)
  4. User visits reset link → POSTs new password + token to /api/auth/reset-password
  5. Token hash verified; new password bcrypt-hashed and saved

Admin Detection

Admin status is determined at token-sign time by checking the user's email against the ADMIN_EMAILS environment variable (comma-separated list). The isAdmin flag is embedded in the JWT payload.

3.4 Transactions Engine

The transaction system supports CRUD operations, bulk operations, file uploads, and a streaming background import job queue.

File Upload & AI Analysis

  1. Multer accepts Excel (.xlsx, .xls) and PDF files (max 10 MB)
  2. ExcelJS parses Excel sheets; pdf-parse extracts PDF text
  3. Google Gemini AI analyzes extracted content to auto-classify transactions (category, type, amount, date)
  4. Results returned as structured JSON for user review before saving

Background Import Jobs

Large imports use a streaming job queue to avoid HTTP timeouts:

  1. Create Job: POST /api/transactions/import-jobs → returns jobId
  2. Stream Status: GET /api/transactions/import-jobs/:id/stream (SSE)
  3. Add Chunks: POST /api/transactions/import-jobs/:id/chunks
  4. Finalize: POST /api/transactions/import-jobs/:id/finalize
  5. Retry / Cancel: POST .../retry or .../cancel

7. Security

🔐 Authentication
  • Stateless JWT tokens (72h expiry)
  • bcrypt password hashing (10 salt rounds)
  • Auth rate limiter: 10 attempts / 15 min in production
  • Password reset tokens stored as SHA-256 hashes only
  • Reset tokens expire after 1 hour
  • isAdmin flag embedded in JWT at sign time
🛡️ HTTP Security
  • Helmet sets: CSP, HSTS, X-Frame-Options, X-Content-Type-Options
  • CORS: production restricts to explicit origin whitelist
  • Global rate limiter: 2000 req / 15 min per IP
  • Trust proxy enabled for correct IP with Nginx / Render
  • Request body size limit: 25 MB
🔑 API Keys
  • Zero-knowledge storage: only SHA-256(key) stored
  • Constant-time comparison to prevent timing attacks
  • Scope-based access control on every v1 endpoint
  • Keys can be revoked (isActive = false)
  • Optional expiry dates
  • Last-used timestamp tracking
✅ Input Validation
  • All auth endpoints use express-validator rules
  • Transaction query params validated with Zod schema
  • File uploads restricted to .xlsx, .xls, .pdf (type + extension)
  • Max file size enforced at Multer level (10 MB)
  • Mongoose schemas provide secondary type enforcement
🚦 Error Handling
  • Centralized error middleware — no raw errors leak to client
  • Stack traces hidden in production
  • Request IDs for tracing errors across logs
  • Unhandled promise rejections caught globally
🗄️ Data Security
  • Card numbers are never stored — only brand, last4, expiry
  • Admin emails never appear in user-facing lists
  • File access is scoped by authenticated user ID
  • MongoDB connection with Mongoose strict schema enforcement

11. Conclusion & Future Work

11.1 Conclusion

This graduation project has demonstrated the technical feasibility and practical value of integrating large language model (LLM) capabilities within a conventional financial management software architecture. The AI Accountant system successfully achieves all primary research objectives: it provides SME operators with real-time financial dashboards and KPI analytics, enables AI-driven natural-language querying via a conversational chatbot interface, automates transaction extraction from uploaded documents using Google Gemini's multi-modal analysis capabilities, and generates fully formatted spreadsheets from plain-text descriptions using the Groq LLaMA 3.3-70B inference engine.

The implementation adheres to contemporary software engineering best practices, including layered RESTful API design, stateless JWT-based authentication, scope-controlled API key authorization, bcrypt password hashing, and a defense-in-depth HTTP security model enforced through the Helmet middleware suite. The dual data-store architecture — which transparently falls back to a local JSON-based persistence layer in the absence of a live MongoDB connection — substantially reduces the barrier to entry for local development and testing workflows, representing a pragmatic engineering contribution.

The tiered subscription model demonstrates a commercially viable pathway for platform monetization, while the versioned public REST API (v1) with scope-based API key authentication enables programmatic third-party developer integration. Collectively, this system constitutes a meaningful contribution at the intersection of enterprise web engineering and applied artificial intelligence, particularly within the domain of SME financial management.

11.2 Limitations

⚠️ Simulated Payment Processing

The subscription billing module employs a simulated payment flow rather than a live payment gateway integration. Real-world deployment would necessitate integration with a PCI-DSS-compliant payment processor such as Stripe or PayPal, and would require handling recurring billing, refunds, and dispute resolution.

⚠️ Local File Storage

Uploaded files and the JSON-based usage store are persisted on the local server filesystem, which is incompatible with horizontally scaled, multi-instance deployment environments. A distributed object storage solution (e.g., Amazon S3, Google Cloud Storage) would be required for production-scale, high-availability deployments.

⚠️ External AI Dependency

All AI feature responses are contingent on the availability of external API services from Groq and Google Gemini, and are subject to third-party rate limits, inference latency, and pricing changes. High-concurrency scenarios may experience elevated response times on AI-powered endpoints.

⚠️ Single-Tenant Data Model

The current data model is designed for single-user tenancy, with data isolation enforced by authenticated user ID. Support for organizational accounts, multi-user collaborative teams, or enterprise multi-tenancy would require substantial schema redesign and role-based access control enhancements.

11.3 Future Work

The following directions are identified as high-priority areas for future research and development:

  • Live Payment Gateway Integration: Replacing the simulated checkout flow with a production-grade, PCI-DSS-compliant payment processor to enable real subscription revenue collection and automated recurring billing management.
  • Automated Tax Reporting: Extending the KPI analytics engine to generate jurisdiction-specific tax reports and integrate with government electronic filing APIs (e.g., VAT returns, income tax declarations).
  • OCR Enhancement for Scanned Documents: Implementing Optical Character Recognition (OCR) post-processing to improve transaction extraction accuracy from scanned or image-based PDF financial documents where embedded text is unavailable.
  • Multi-Currency & Localization Support: Incorporating real-time foreign exchange rate feeds and locale-aware number formatting to support multi-currency transaction recording and consolidated international financial reporting.
  • Mobile Application Development: Developing a cross-platform companion mobile application (React Native or Flutter) to extend platform accessibility to mobile business operators and enable push-notification financial alerts.
  • Predictive Financial Analytics: Applying time-series forecasting models (e.g., ARIMA, LSTM neural networks) to historical transaction data in order to project future cash flow, revenue trends, and expense trajectories.
  • Domain-Specific Model Fine-Tuning: Fine-tuning a compact language model on accounting and financial domain corpora to reduce dependency on general-purpose third-party API services and improve the accuracy of domain-specific financial reasoning and categorization.
  • Comprehensive Audit Trail & Regulatory Compliance: Implementing a tamper-evident, append-only audit log for all financial record modifications to satisfy regulatory compliance requirements such as Sarbanes-Oxley (SOX) and International Financial Reporting Standards (IFRS).
